# PiliMini

一个用鸿蒙原生界面开发的极简 B 站客户端，主要面向日常看视频和后台听视频。

这个项目起于个人使用需求：喜欢 [PiliNara](https://github.com/dev4harmony/PiliNara/tree/ohos) 的界面和交互，希望用原生界面实现日常播放、浏览、弹幕、收藏和动态，并控制体积、内存与后台负载。

当前版本 **0.3.0**，仍在开发和优化中。项目以 Nara 为 UI、动效与交互参考，尚未完成全部细节的同机对照验收；原生开发也不代表已经达到更低内存或耗电。

## 已实现功能

| 模块 | 可以做什么 |
| --- | --- |
| 登录 | 扫码登录、保持登录、退出登录；未登录也可以浏览基础内容 |
| 首页与搜索 | 推荐双列、热门横卡、刷新和分页、卡片局部菜单；重复点底部导航回顶，顶端再点或双击刷新；视频关键词搜索、本地搜索历史 |
| 视频详情 | 简介、分 P 横条与选集面板、合集及分节、相关推荐；缓存、收藏、稍后再看及状态反馈 |
| 视频播放 | 横竖视频、全屏、清晰度和倍速、软硬解设置；拖动进度、双击暂停、长按倍速；系统媒体音量与窗口亮度手势；在线按分 P 续播 |
| 弹幕 | 普通滚动、顶部、底部弹幕，默认开启并记忆选择；区域、透明度、字号、速度、密度和类型设置；本机关键词 / 发送者屏蔽、附近已加载弹幕、复制及本视频隐藏 |
| 后台与系统控制 | 后台听视频、系统媒体卡、锁屏控制和系统支持时的实况窗；收到系统可恢复的音频中断事件后，按原播放意图恢复；回前台恢复视频 |
| 评论与图片 | 按热度 / 时间排序、楼中楼、点击预览定位并高亮对应回复；评论和动态图片查看、缩放与原位返回；评论以浏览为主 |
| 收藏与稍后再看 | 带封面的收藏夹分页列表、我的页横向预览、新建收藏夹、收藏增删、稍后再看增删 |
| 动态 | 关注动态，按全部 / 视频 / 图文筛选，查看图文和转发内容；当前分类支持导航回顶和刷新 |
| UP 主空间 | 资料、主页、动态、视频和图文投稿、合集 / 系列、空间内搜索、公开收藏；关注 / 取消关注、拉黑 / 解除拉黑 |
| 观看历史 | 观看进度上报、历史列表、继续播放 |
| 下载与离线 | 原生下载队列、暂停 / 继续 / 重试；合集与分 P 按原序整理，有序文件夹和批量管理；离线续播、范围内上下集与自动连播 |
| 外观与设置 | 跟随系统深浅色、沉浸光感材质、音视频设置、图片缓存管理 |

内容是否可看、画质是否可用，仍取决于账号权限和服务端接口。当前没有关注列表、直播、番剧影视、投屏或多账号；弹幕暂不包含发送、离线文件、高级 / 代码弹幕和账号规则同步。

在线续播按视频和分 P 保存进度；开头不足 3 秒不恢复，结尾 10 秒内按已看完处理。离线续播超过 5 秒保存观看目标，并保留原来的全部 / 合集 / 文件夹播放范围；离线切集保留全屏和倍速。下载目前使用包含音轨的 MP4，不支持的多段源会明确提示。

## 技术栈

- **界面**：ArkTS + ArkUI，Stage 模型，V1 状态管理，单 `entry` 模块。
- **播放器**：C++ / Node-API 桥接单个鸿蒙 libmpv，与 Nara 使用同源内核。视频和 DASH 音轨由同一内核同步，界面不依赖 Flutter。
- **系统媒体能力**：原生 AVSession、后台音频长时任务；后台播放约 10 秒后关闭视频轨，回前台恢复，后台暂停立即停视频轨。
- **图片**：按展示尺寸请求 CDN 缩略图，内存受字节预算约束，磁盘只保留小缩略图；查看原图按需加载，不长期落盘。
- **网络与存储**：NetworkKit、WBI 签名、系统 Preferences、AssetStore 保存登录凭据；请求直接访问服务端，没有自建代理后端。
- **二维码**：`@ohos/zxing`。

工程目标 SDK 为 API 26，最低兼容配置为 HarmonyOS 6.0.2（API 22）；主要验证环境是 API 26 模拟器与鸿蒙真机，较低系统版本尚未完整验证。正式构建仅包含 arm64-v8a。

## 性能与资源控制

控制体积、内存和后台负载是本项目的主要开发目标，目前已做的处理包括：

- **单播放内核**：视频与 DASH 音频共用一个 libmpv，避免维护两套独立播放器；关闭本项目未使用的内置 Lua 脚本。
- **后台减少工作**：播放转后台约 10 秒后停止视频解码与渲染，保留音频；常规状态快照从前台 500ms 降为后台 5 秒，稳定暂停时停止定时快照，系统控制仍由事件即时处理。
- **图片按需缓存**：列表请求对应尺寸的缩略图，原图按需查看且不落盘；主图片缓存、大图缓存各设 16MiB 预算，磁盘只收成功解码且不超过 512KiB 的 CDN 缩略图。内存预算只限制缓存自身，不包含页面、纹理和临时解码内存。
- **减少重复唤醒和写入**：原生事件线程阻塞等待，播放状态按实际值变化通知，视频尺寸由重配置事件和常规快照更新，减少逐帧重复通知带来的界面更新；常规观看进度和本地续播保存前台 15 秒、后台 30 秒，暂停、退出等状态切换及时保存；不可见页面不持续刷新列表。
- **减少个人页开销**：历史和收藏横向列表只加载可见卡片及少量预备项；同账号从历史页返回不重拉、重建缩略图。收藏封面直接随分页接口返回，去掉逐个收藏夹补图的额外请求及其独立缓存。
- **下载资料不重复存放**：合集和分 P 从任务元数据派生，文件夹只保存有序引用，不复制视频。进度变化只更新活动条目和字节差额，不重新分组、序列化文件夹或重建封面；列表使用懒加载。离线播放不请求在线详情、评论和云端历史。
- **弹幕控制开销**：分段按需加载，有界缓存与并发，使用单 Canvas 和字形缓存；弹幕位置连续缓校播放器快照的小误差，附近列表和屏蔽列表按可见项加载；关闭、暂停或不可见时停止相应帧驱动，后台取消弹幕请求，不增加播放器高频轮询。
- **系统控制按事件同步**：媒体音量读回与硬件音量事件同步；亮度只修改当前窗口，退出恢复原窗口设置；没有为两者增加轮询。

已有真机与模拟器的播放、后台及循环退页采样，但结果只覆盖对应构建和路径。弹幕长时播放的模拟器采样仍观察到 native 内存增长；首次详情布局和首次进入评论仍有耗时峰。尚未证明全应用资源增长有界，也未完成与 Nara 的同条件性能对照或真机放电耗电测试，暂不给出省内存、省电百分比或“无泄漏”保证。

## 当前进度

主要浏览和播放链路已有模拟器及真机验证，近期分 P / 合集交互、音频中断恢复、系统音量 / 亮度与全屏横屏翻转也已得到真机使用确认。弹幕渲染与列表滚动已优化，并修复重复播放状态通知引起的周期性顿挫；当前真机使用反馈基本顺滑。长时间播放的资源占用与耗电仍持续观察，电话、蓝牙等组合场景继续补充验证；系统未发恢复事件或其他应用未释放焦点时，播放器保持暂停。

后续优先处理弹幕流畅度、长时资源增长和起播布局，再补我的关注列表、BV / 链接打开等浏览能力。模拟器仍使用同源 O0 调试内核，优化构建的图形初始化问题未解决；UI / 动效与 Nara 的完整同机对照和真机放电测试也待完成。

## 构建

当前命令行工具主要按 **Windows + DevEco Studio** 环境验证。需要安装包含 API 26 与 Native SDK 的 DevEco Studio，并让 Node.js、ohpm 可用。真机安装需要自行配置开发签名，仓库不提供签名材料。

先在项目根目录执行：

```powershell
# 路径替换为自己的 DevEco Studio 安装目录
$env:DEVECO_STUDIO_HOME = "C:\Program Files\Huawei\DevEco Studio"
$env:Path = "$env:DEVECO_STUDIO_HOME\tools\ohpm\bin;$env:Path"

# 下载并校验 Nara 同源 arm64 播放依赖，再安装 ArkTS 依赖
node tools/prepare-player-deps.cjs
ohpm install

# 生产构建仅 arm64；输出为未签名 HAP
.\hvigorw.bat assembleHap --no-daemon -p buildMode=release
```

输出位置：`entry/build/default/outputs/default/entry-default-unsigned.hap`。可通过 DevEco Studio 使用自己的签名安装到设备。

模拟器另需 Python 3 和 Git Bash，先准备 x86_64 调试内核：

```powershell
node tools/build-player-simulator.cjs --sdk "<Native SDK目录>" --python "<python.exe>" --bash "<bash.exe>"
.\hvigorw.bat assembleHap --no-daemon
```

依赖下载与构建产物写入 `.local-deps/` 和 `entry/libs/`。上游源码、补丁与 SHA256 记录在 `tools/player-simulator-sources.json`，arm64 发布库校验见 `tools/prepare-player-deps.cjs`。

## 代码结构

```text
entry/src/main/
├── ets/pages/        首页、搜索、播放详情、动态、UP 空间等页面
├── ets/components/   公共卡片、评论、图片和播放器界面
├── ets/service/      视频、登录、收藏、动态、下载等接口与业务
├── ets/infra/        网络、签名、登录凭据、存储、图片及播放器控制
├── ets/model/        数据模型
├── cpp/              单 libmpv 的 Node-API 桥接和接口头文件
└── resources/        应用资源、深浅色、页面注册
```
