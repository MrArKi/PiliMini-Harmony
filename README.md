# PiliMini

一个用鸿蒙原生界面开发的极简 B 站客户端，主要面向日常看视频和后台听视频。

这个项目起于个人使用需求：喜欢 [PiliNara](https://github.com/dev4harmony/PiliNara/tree/ohos) 的界面和交互，但希望只保留自己常用的部分，并探索原生界面在体积、内存和后台运行方面的表现。因此参考 Nara 重新实现客户端，重点放在播放、浏览、收藏和动态上，没有加入弹幕等功能。

当前版本 **0.2.0**，仍在开发和优化中。项目以 Nara 为 UI、动效与交互参考，尚未完成全部细节的同机对照验收；原生开发也不代表已经达到更低内存或耗电。

## 已实现功能

| 模块 | 可以做什么 |
| --- | --- |
| 登录 | 扫码登录、保持登录、退出登录；未登录也可以浏览基础内容 |
| 首页与搜索 | 推荐、热门、刷新和分页；关键词搜索、本地搜索历史 |
| 视频详情 | 简介、分 P / 选集、相关推荐；缓存、收藏、稍后再看及状态反馈 |
| 视频播放 | 横竖视频、全屏、清晰度和倍速、软硬解设置；拖动进度、双击暂停、长按倍速、音量和亮度手势；在线视频下次打开从上次进度续播 |
| 后台播放 | 切到后台后继续听；系统媒体卡、锁屏控制和系统支持时的实况窗；返回应用恢复视频 |
| 评论与图片 | 按热度 / 时间排序、楼中楼、评论和动态图片查看、缩放与原位返回；评论以浏览为主 |
| 收藏与稍后再看 | 收藏夹浏览、新建收藏夹、收藏增删、稍后再看增删 |
| 动态 | 关注动态，按全部 / 视频 / 图文筛选，查看图文和转发内容 |
| UP 主空间 | 资料、主页、动态、视频和图文投稿、合集 / 系列、空间内搜索、公开收藏；关注 / 取消关注、拉黑 / 解除拉黑 |
| 观看历史 | 观看进度上报、历史列表、继续播放 |
| 下载与离线 | 下载队列、进度管理、离线播放、删除缓存，可设置仅 Wi-Fi 下载 |
| 外观与设置 | 跟随系统深浅色、沉浸光感材质、音视频设置、图片缓存管理 |

内容是否可看、画质是否可用，仍取决于账号权限和服务端接口。本项目没有直播、番剧影视、弹幕、投屏、多账号等完整客户端功能。

在线续播按视频和分 P 保存进度；开头不足 3 秒不恢复，结尾 10 秒内按已看完处理。离线播放目前尚未保存跨次播放进度。

## 技术栈

- **界面**：ArkTS + ArkUI，Stage 模型，V1 状态管理，单 `entry` 模块。
- **播放器**：C++ / Node-API 桥接单个鸿蒙 libmpv，与 Nara 使用同源内核。视频和 DASH 音轨由同一内核同步，界面不依赖 Flutter。
- **系统媒体能力**：原生 AVSession、后台音频长时任务；后台播放约 10 秒后关闭视频轨，回前台恢复，后台暂停立即停视频轨。
- **图片**：按展示尺寸请求 CDN 缩略图，内存受字节预算约束，磁盘只保留小缩略图；查看原图按需加载，不长期落盘。
- **网络与存储**：NetworkKit、WBI 签名、系统 Preferences、AssetStore 保存登录凭据；请求直接访问服务端，没有自建代理后端。
- **二维码**：`@ohos/zxing`。

工程目标 SDK 为 API 26，最低兼容配置为 HarmonyOS 6.0.2（API 22）；主要验证环境是 API 26 模拟器与鸿蒙真机，较低系统版本尚未完整验证。正式构建仅包含 arm64-v8a。

## 性能与资源控制

控制体积、内存和后台负载是本项目的主要开发目标，目前已做的处理包括：

- **单播放内核**：视频与 DASH 音频共用一个 libmpv，避免维护两套独立播放器；关闭本项目未使用的内置 Lua 脚本。
- **后台减少工作**：播放转后台约 10 秒后停止视频解码与渲染，保留音频；常规状态快照从前台 500ms 降为后台 5 秒，稳定暂停时停止定时快照，系统控制仍由事件即时处理。
- **图片按需缓存**：列表请求对应尺寸的缩略图，原图按需查看且不落盘；主图片缓存、大图缓存各设 16MiB 预算，磁盘只收成功解码且不超过 512KiB 的 CDN 缩略图。内存预算只限制缓存自身，不包含页面、纹理和临时解码内存。
- **减少重复唤醒和写入**：原生事件线程阻塞等待；常规观看进度和本地续播保存前台 15 秒、后台 30 秒，暂停、退出等状态切换及时保存；不可见页面不持续刷新列表。

2026-10-18 的真机 arm64 release 验证结果如下，数据来自单台设备和固定测试视频：

| 检查项 | 实测结果 |
| --- | --- |
| HAP 包体 | 签名包约 **12.73MiB**，未签名包约 **12.68MiB**；仅包含 arm64 原生库 |
| 反复进入、退出 | 同一进程完成 **40 轮 UP 空间进退 + 8 轮完整退页 / 重进**；旧视频 Surface 输出缓冲残留为 0，退页后解码实例、播放器事件线程、媒体会话及音频输出均为 0 |
| 循环后退页内存 | 播放、暂停两组各 20 轮，分别退出并静置 35 秒，进程 PSS 为 **116.07MiB / 118.75MiB**；这是退页后的读数，播放峰值需另行测量 |
| 后台音频 | 进入后台 13 秒时，视频解码实例为 0，音频输出和媒体会话各 1；系统暂停 / 恢复及回前台出图通过 |

上述结果覆盖指定路径，不代表全应用无泄漏；尚未完成与 Nara 的同条件性能对照及真机放电耗电测试，因此暂不给出“比 Nara 更省内存”或省电百分比。

## 当前进度

主要浏览和播放链路已在模拟器及真机上进行验证，仍有以下重点待完善：

- 已修复真机退出播放器时旧 Surface 输出缓冲残留及 AVSession 控制监听未解绑；同进程 40 轮 UP 空间进退、8 轮完整退页 / 重进检查中，未再出现旧输出缓冲累积，退出后媒体服务资源归零。这是指定路径的结果，不能代表全应用无泄漏。
- 图片磁盘缓存曾因小图请求原图而增长过快，已调整为缩略图缓存，原图不持久缓存；仍需持续观察实际浏览占用。
- 模拟器反复重建播放器时，`/dev/teleport_express` 图形驱动句柄仍增长，**模拟器资源验收未通过**。当前使用同源 O0 调试内核，其优化构建的图形初始化问题也尚未解决；模拟器表现不能代替真机硬解、听感验收。
- 真实放电耗电和全部 UI / 动效与 Nara 的同机对照仍待完成。

适合作为开发中的源码项目交流，不应将上述状态理解为稳定版或“无泄漏、低耗电”保证。

## 构建

当前命令行工具主要按 **Windows + DevEco Studio** 环境验证。需要安装包含 API 26 与 Native SDK 的 DevEco Studio，并让 Node.js、ohpm 可用。真机安装需要自行配置开发签名，仓库不提供签名材料。

先在项目根目录执行：

```powershell
# 路径替换为自己的 DevEco Studio 安装目录
$env:DEVECO_STUDIO_HOME = "C:\Program Files\Huawei\DevEco Studio"
$env:Path = "$env:DEVECO_STUDIO_HOME\tools\ohpm\bin;$env:Path"

# 下载并校验 Nara 同源 arm64 播放依赖，再安装 ArkTS 依赖
node tools/prepare-player-deps.cjs
ohpm install

# 生产构建仅 arm64；输出为未签名 HAP
.\hvigorw.bat assembleHap --no-daemon -p buildMode=release
```

输出位置：`entry/build/default/outputs/default/entry-default-unsigned.hap`。可通过 DevEco Studio 使用自己的签名安装到设备。

模拟器另需 Python 3 和 Git Bash，先准备 x86_64 调试内核：

```powershell
node tools/build-player-simulator.cjs --sdk "<Native SDK目录>" --python "<python.exe>" --bash "<bash.exe>"
.\hvigorw.bat assembleHap --no-daemon
```

依赖下载与构建产物写入 `.local-deps/` 和 `entry/libs/`，均不入库。上游源码、补丁与 SHA256 记录在 `tools/player-simulator-sources.json`，arm64 发布库校验见 `tools/prepare-player-deps.cjs`。

## 代码结构

```text
entry/src/main/
├── ets/pages/        首页、搜索、播放详情、动态、UP 空间等页面
├── ets/components/   公共卡片、评论、图片和播放器界面
├── ets/service/      视频、登录、收藏、动态、下载等接口与业务
├── ets/infra/        网络、签名、登录凭据、存储、图片及播放器控制
├── ets/model/        数据模型
├── cpp/              单 libmpv 的 Node-API 桥接和接口头文件
└── resources/        应用资源、深浅色、页面注册
```
